How to label

Label alone, and don't discuss items with the other reviewer until both of you have exported everything. You cannot tell which tool reported a flow, by design.

Flows

  • Real flow: the data can travel from the source to the sink, along these steps or an equivalent path, in some execution the code allows, and the source holds personal data.
  • Path breaks: a step does not pass the value on, or the sink does not receive it. A "sink" that is the application's own response is also a broken path. Cite where it breaks.
  • Not personal: the value does reach the sink, but it is not personal data.
  • Category right: at least one category shown is right for the source. Generic user is right whenever the data is personal.
  • Judge reachability, not policy: sending an email address to the email provider is still a real flow.

Coverage gaps

  • Follow the unresolved call by hand. Hides a flow if personal data reaches a log, third party, LLM, outbound HTTP or browser storage through it; cite that sink.

Call sites

  • First: is this call really a sink (log, third party, LLM, outbound HTTP, browser storage)? Toasts, the app's own responses, in-process events and database writes are not.
  • If it is: does personal data reach it from anywhere in the application? Give categories and one source.

Personal data

  • Anything Fideslang files under user.*: names, contact details, identifiers that point to a person (a user's database id included), IP addresses, credentials, content a user wrote. Organisation data is not, unless it identifies a person.
  • Stuck after about five minutes? Choose Unsure and say why in the note.

Pace

  • Two to three minutes per item. Take a break every hour; label quality drops after that.
