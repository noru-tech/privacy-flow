# PF006: Personal data reaches outbound HTTP with a non-literal host

**A flow of personal data to an outbound HTTP call (`fetch`, axios, got, ky, `requests`, `httpx`, aiohttp, urllib) whose host is not a literal in the code is a finding.**

| | |
| --- | --- |
| Rule ID | `PF006` |
| Default severity | `warning` (warning (SARIF)) |
| Fails the default policy (`fail_on: medium`) | no |
| Fixtures | [`tests/fixtures/ts/pf006-fail`](../../tests/fixtures/ts/pf006-fail) (fails), [`tests/fixtures/ts/pf006-pass`](../../tests/fixtures/ts/pf006-pass) (passes), and the Python equivalents |

## Why it matters

A record of processing names its recipients, and transfers outside the EEA need a basis. When
the URL is computed at run time (`process.env.WEBHOOK_URL`, a configuration value, a client
created with a base URL elsewhere) the code does not say who receives the data, so neither can
the analysis. PF006 marks those flows so that the destination is established and recorded,
rather than assumed.

## When it fires

- the sink's class is `http`, and
- its host is `dynamic`: the URL argument is not a string literal (or a template or concatenation
  that starts with one), or the call uses a client's configured base URL.

Relative URLs (`/api/audit`) are the application's own origin and are not findings. A literal host
names the processor, which PF002 then checks against the declared processors. Credentials sent in
request headers are authentication, not data, and do not fire PF006.

## Controls

- GDPR Art. 30 — records of processing name the recipients.
- GDPR Art. 44 — transfers to third countries need a basis; an unknown host is an unknown country.

These mappings are identifiers with Noru's own short gloss; no normative text from any standard is
quoted. They are a guide for control owners, not a compliance claim, and are pending review by a
privacy lawyer or Noru's compliance lead
([control mapping](../control-mapping.md)).

## Failing example

Fixture: [`tests/fixtures/ts/pf006-fail/`](../../tests/fixtures/ts/pf006-fail/). An email address is posted to a URL read from the environment.

```console
$ piiflow -q scan tests/fixtures/ts/pf006-fail -f json | jq -r '.findings[] | "\(.rule_id) \(.severity) | \(.message)"'
PF006 warning | user.contact.email from `user.email` (src/webhook.ts:3) is sent over HTTP to a host computed at run time, at src/webhook.ts:3
```

`piiflow explain <finding ID>` prints the full chain of hops from the source to the sink, with the
source line of each.

## Passing example

Fixture: [`tests/fixtures/ts/pf006-pass/`](../../tests/fixtures/ts/pf006-pass/). The URL starts with a literal host of a declared processor (`hosts: [crm.acme.example]`), and the second call is relative.

## How to fix

- Make the host explicit in code (a constant), so the processor is named and PF002 can check it.
- Otherwise record where the URL comes from and who receives the data in a disposition.

## Recording a disposition

A finding is never deleted. To record a human decision about it, edit only the finding's
`disposition` in `.privacy-flow/flows.json` (`accepted`, `remediated` or `false_positive`, with
`owner`, `decided_at`, `rationale`, and `remediated_at` or an optional `expires_at`), then run
`piiflow check .privacy-flow/flows.json --as-of YYYY-MM-DD`. The date is required because the
machine clock is never read. A disposition suppresses the finding from the threshold decision on
that date and leaves the finding, its flow and the summary intact; the next `scan` carries it over
by finding ID, which does not depend on line numbers. Exact rules:
[dispositions](../output.md#dispositions).

```json
{
  "status": "accepted",
  "owner": "privacy@example.com",
  "decided_at": "2026-10-01",
  "expires_at": "2026-12-31",
  "rationale": "WEBHOOK_URL is the customer's own endpoint, configured per tenant; covered by the customer DPA §4.",
  "remediated_at": null
}
```

To change how the rule is enforced rather than record a one-off decision, set its severity or
disable it under `policy.rules.PF006` in [`.privacy-flow.yml`](../configuration.md#policy).
